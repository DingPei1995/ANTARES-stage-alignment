数据：2026-11-15 的 SPEM 原始数据（`CavData/*.nxs`，40 个扫描），用 ARPES viewer 读取。
样品：Cav（graphene），gating plate，波带片 + OSA，hv 95 eV。

- gating plate（Cav）：`configs/calibration_2026-11-20_142936_zone_plate.json`
- standard plate：`configs/calibration_2026-11-20_142937_zone_plate.json`

当天更早的 `calibration_2026-11-20_141536_zone_plate.json` 已被取代：它沿用 11-15 的 working distance（53.7502），把点放在原点上游 0.033 mm。
分析脚本与图：`RealSampleCalibration/docs/reports/src/cav_2026-11-20/`。

## 1. 一句话结论

- ZPS 与 sample stage 的相对位置关系**被确认**。所有 SN 不动的数据都能用同一组参数解释到 ±0.016 mm（ZPS）和 ±5 µm（边的位置），只需要一个修正：anchor 上的点其实在 **ZPS 53.717** 对焦，不是 53.75。
- SN 电机的读数/移动精度**没有发现误差**。SRz 0 时 SN 在 −1.86…+1.15 mm 范围内移动，结果都准到 0.011 mm 以内。
- 唯一的矛盾是两组"SRz −25 且 SN 移动过"的数据：焦点比预测低 0.20 / 0.27 mm（ZPS），但横向 PIX 只差 2 / 9 µm。这是**纯沿光束方向**的偏差。SN 读数误差、标记误差和 SRz 角度误差都解释不了它（见第 4 节），原因还没定。
- 程序随之调整（第 6 节）：*Correct H* 改名 *Set SN by eye*（粗测），*Move found sample…* 改为 *Fine tunings by ZPS/CPS*，由聚焦元件位置修正样品位置和高度，并取代 *Found here*；CadCollision 改为读最新的 ZP config。

## 2. 方法

1. 只用 ZPS 步长 0.01 / 0.02 的细扫（PIX × ZPS），并去掉边不清楚的扫描。去掉的有：粗扫 10-33-19、12-00-24、12-49-27；边不清楚的 15-00-22；只有 4 行的 14-21-48。
2. 去掉没测到的点（时间戳为 NaN）。文件里这些点被填成常数，不去掉会把边的方向判反。
3. 每一行 ZPS 找最陡的边（梯度最大，抛物线细化），边位置精度约 0.5 µm。边最锐的那行 = 焦点。同一组电机的两次扫描合在一起处理。
4. 用 2D map 认出每条线扫扫的是哪条边：
   - **A**：器件中间竖条的右沿，PIY 40，下降沿。SRz 0 anchor 线扫（11-00-33、11-03-42）。
   - **B**：同一竖条的左沿，PIY 10–40，上升沿。SRz 0 的 4 个 slide，以及 SRz −5 / −10 / −15 / −20 系列。
   - **C**：竖条顶部"头"的左沿，PIY 170–180。SRz −25 的两组。
5. 用模型从 ST / SZ / SN / PIX / PIY 算出边在 plate 上的绝对位置（u, v）。再算光束打到表面那一点沿光束的位置，换成 ZPS，和实测焦点比较。表面位置与 PIX 无关，所以 ZPS 的比较不受"点有没有定准"的影响。

文件里记录的电机值和笔记略有不同：SRz −25 最后一组的 SZ 是 36.546，不是 36.54。所以 PIY 的矛盾从 14 µm 缩小到 8 µm。

- 4 个 slide 平均 **53.717 ± 0.008**。anchor 线扫本身给 53.69–53.72，另一块区域（10-38-38，SRz 0）给 53.72。
- ZPS 与沿光束的位移是 **1:1**。11-15 报告里的"比例 1.015 / 0.95–0.97"其实是把 anchor 焦点当成 53.75 造成的零点误差。

### 3.2 SRz −5…−20（SN 不动）：SRz 轴

这一系列没有把跟踪点准确放到 PIX 138 / PIY 142，但线扫精确测到了 B 边的 PIX。B 边在 plate 上的位置由 SRz 0 的 slide 定出，和轴无关。所以这些数据可以同时给出横向（边 PIX）和沿光束（焦点）两个方向的信息。

只用这些 SN 不动的数据拟合 SRz 轴：
- **offset_t −0.188 ± 0.031，offset_n 2.361 ± 0.023**，chi² 9.0，自由度 6。
- 残差：焦点 ≤ 0.016 mm，边位置 ≤ 5 µm。
- 独立检验 SRn 140 / SRz −15（没有参加拟合）：预测 PIX 139（实测 138）、ZPS 54.34（笔记 54.33）。

被否定的方案：上一轮用两组"SN 移动"的 SRz −25 数据拟合的轴（offset_t +0.330 / offset_n 2.668）。它让 SRz −5…−20 的焦点差 +0.06…+0.20 mm，边位置差 16–24 µm。

## 4. 关于"SN 电机读数/移动有误差"

现有数据**不支持**这个说法：

1. **SRz 0 的 slide 证明 SN 移动是准的。** 在 −1.86…+1.15 mm 范围内（包括和 SRz −25 那两组同样大的 −1.86 mm），焦点误差 ≤ 0.011 mm，边位置 ≤ 10 µm。
2. **SN 的误差应该同时出现在横向。** SN 沿 n = (1, 1)/√2 移动，一半在横向、一半沿光束。要造成沿光束 0.2–0.27 mm 的偏差，SN 要错约 0.3–0.4 mm，同时点在横向会移动 ≥ 0.2 mm，也就是 PIX 差 200 µm 以上。实测只差 2–9 µm。
3. **ST、SN 都在 SRz 下方。** 转 SRz 不改变它们在实验室中的方向。即使 ST/SN 装在 SRz 上面，1.5–1.8 mm 的 slide 在 SRz −25 也会带来约 0.7 mm 的横向位移，同样看不到。

能排除的其他解释：
- **标记误差**（照片上 D1 的位置、map 上读点）：照片标记只让整个 plate 坐标系平移，对所有组的影响相同，造不出只在两组上出现的偏差。map 上读点 ±4–10 µm，对应的 ZPS 变化 < 0.01 mm。要补 0.2 mm，SRz 轴得挪约 0.5 mm，边位置会差 100 µm 以上。
- **SRz 角度误差**：0.2 mm 需要约 2°，横向会差约 200 µm。
- **ZPS 比例**：slide 证明是 1:1，范围一直到 51.17。
- **H**：H = 1.0 是测量值。表面倾斜约 1°，在 C 边和 B 边之间（v 差 0.13 mm）只造成约 2 µm。

剩下的可能：
- 只在 SRz −25 才出现的问题（没有 SN 不动的 SRz −25 数据，无法检验）；
- 在 SRz −25 时同时有 ST 和 SN 误差，正好相互抵消横向分量（不太可能）；
- 在 SRz −25 那组扫描里，焦点判断本身有系统偏差（边分析和笔记一致，可能性不大）。

**下次上线可以区分的两个测量：**
1. SRz −25，SN 不动，测焦点；
2. SRz −10，SN 移动约 1.5 mm（ST 补偿），测焦点和点位置。

如果第 1 个对、第 2 个错，问题在"SRz ≠ 0 时移动 SN"；如果第 1 个就错，问题在 SRz −25 本身。

确定的前提（用户，2026-11-20）：

## 6. 程序改动（同日，用户决定）

起因：今天的分析说明，"聚焦元件焦距不变，所以对焦时的 ZPS / CPS 就是样品表面沿光束的位置"这一点，比目测相机参考线（约 ±0.05 mm）精确得多（ZP 约 ±0.02 mm，对应 H 约 ±0.014 mm）。两个按钮的名字和功能因此调整。

| 按钮（页面） | 以前 | 现在 |
|---|---|---|
| **Set SN by eye**（Samples 页，原 *Correct H*） | 由目测 SN 算 H，并锁定该 SN | 功能不变，标明是粗测（±0.05 mm）。按 *Samples placed → Stage* 时先询问：样品上表面到达参考线时的 SN 是否就是这个值（SN 框里输入了但未设置的值也会问） |
| **Fine tunings by ZPS/CPS**（Stage & Optics 页，原 *Move found sample to analyzer focal plane*） | 把找到的样品沿光束拉回分析器焦平面；只在 SRz 转动后检查 H；SRz 0 时算出 H 但不保存 | 按钮下一句说明：聚焦元件的焦距是精确值，所以能同时修正样品位置、高度并拉回分析器焦点。**SRz 0**：由焦点修正 Δx（该样品）、Δy（样品托落座偏移，所有样品的 SZ）、ΔH（该样品）。**SRz 转动后**：只在一个 ΔH 能同时解释 ST、SZ、ZPS 误差时修正 H。然后 SN（ST 补偿，SZ 不变）把表面拉回焦平面，ZPS / CPS 回到 config 中的精确值 |
| *Found here*（Stage & Optics 页） | 假设样品正好在分析器焦点上，修正 Δx、Δy、ΔH | **删除**：*Fine tunings* 在 SRz 0 的修正就是它，只是焦点从聚焦元件读出，不再假设。agent 工具 `align_found_here` 保留（未聚焦、旧 config 换算这两种用法程序里没有） |

其他：
- `core.stage.found_offset` 加了参数 `y`（焦点沿光束的位置；y = 0 即原来的 Found here）。
- 三语用户手册、修正按钮备忘（`docs/correction_buttons_*.md`）、alignment_procedure、README、STAFF_GUIDE、agent 说明和 `API.md` 已同步。测试：258 个通过（新增 SN 确认、SRz 0 修正位置和 H、拒绝不修改等）。
- **CadCollision** 现在默认读最新的 ZP config（与 QuickAlignment 相同，目前是 standard plate 142937），旋转轴随每次新 config 更新。程序中把 `CAD/src` 作为 `quickalignment.cadmodel` 载入的路径代码之前丢失，导致 CadCollision 无法启动，已恢复；22 个 CAD 测试通过，窗口打开正常。
